DNS

DNS significa Domain Name System.

Problema

Pessoas usam nomes. A rede encaminha por endereços IP.

www.universidade.edu.br -> endereço IP

Nuance

DNS não é só nome para IP. DNS é um banco de dados distribuído de registros.

Leitura

O nome completo descreve um caminho na hierarquia.

www.exemplo.com.br

Leia da direita para a esquerda: br, com, exemplo, www.

Servidores DNS

DNS é distribuído para evitar gargalo e ponto único de falha.

Servidor Papel
Raiz aponta para TLDs
TLD responde por com, org, br etc.
Autoritativo mantém registros da zona
Resolvedor local consulta em nome do cliente

Cache

Respostas podem ser guardadas por um tempo indicado pelo TTL.

Resolução DNS

Ideia

O cliente normalmente pergunta ao resolvedor. O resolvedor faz o trabalho de buscar a resposta.

Registros DNS

Tipo Uso comum
A nome para IPv4
AAAA nome para IPv6
CNAME alias para outro nome
MX servidor de e-mail do domínio
NS servidor de nomes da zona
TXT texto, verificações e políticas

Exemplo

exemplo.com.      MX 10 mail.exemplo.com.
mail.exemplo.com. A     203.0.113.20

Mini-lab: DNS Básico

Consulta comum

dig www.google.com

Registros específicos

dig google.com MX
dig google.com NS
dig google.com TXT

O que observar

  • QUESTION SECTION
  • ANSWER SECTION
  • tipos A, AAAA, MX, NS, TXT
  • TTL da resposta

Mini-lab: DNS Por Dentro

Caminho da resolução

dig +trace www.google.com

Comparar UDP e TCP

dig www.google.com
dig +tcp www.google.com

Ideia

DNS normalmente usa UDP em consultas simples, mas também pode usar TCP.

Conexão com transporte

A aplicação escolhe o transporte conforme o serviço necessário.

Correio Eletrônico

E-mail não vai diretamente do computador do remetente para o computador do destinatário.

Ideia

Mensagens passam por servidores e ficam armazenadas até o destinatário acessá-las.

Componentes do E-mail

Componente Papel
MUA agente do usuário
MSA/MTA aceita e transfere mensagens
MDA entrega na caixa postal
Servidor de caixa postal armazena mensagens

Caminho comum

Usuário escreve -> servidor envia -> DNS indica MX -> SMTP transfere -> destinatário acessa.

SMTP, POP3 e IMAP

Protocolo Papel
SMTP envio e transferência entre servidores
POP3 download simples da caixa postal
IMAP acesso e sincronização no servidor

Diferença importante

SMTP envia. POP3 e IMAP acessam a caixa postal.

Erro comum

Não diga que SMTP é o protocolo usado para sincronizar sua caixa de entrada no celular.

Exemplo SMTP

SMTP é textual e roda sobre TCP.

HELO cliente.exemplo.com
MAIL FROM:<ana@exemplo.com>
RCPT TO:<bruno@universidade.edu.br>
DATA
Subject: Aula de redes

Segue o material da aula.
.

Leitura

O protocolo define comandos e respostas para transferir a mensagem.

MIME

O e-mail original foi pensado para texto simples.

MIME permite

Conteúdo Exemplo
texto simples text/plain
HTML text/html
imagem image/png
anexo application/pdf

Ideia

SMTP transporta a mensagem. MIME descreve como representar conteúdos dentro dela.

Web e URL

A Web combina identificação de recursos, hipertexto e transferência por HTTP.

URL

https://www.exemplo.com.br/aulas/redes.html
Parte Valor
esquema https
host www.exemplo.com.br
caminho /aulas/redes.html

Acesso a Uma Página

Ao acessar uma página, o navegador faz várias etapas.

  1. Lê o URL.
  2. Consulta DNS para resolver o host.
  3. Abre conexão TCP com o servidor.
  4. Envia requisição HTTP.
  5. Recebe resposta HTTP.
  6. Renderiza o conteúdo.

Ideia

O usuário vê uma página. A rede executa uma composição de protocolos.

HTTP

HTTP significa HyperText Transfer Protocol.

Modelo

Cliente envia requisição. Servidor envia resposta.

Requisição e Resposta HTTP

Requisição

GET /index.html HTTP/1.1
Host: www.exemplo.com
Accept: text/html

Resposta

HTTP/1.1 200 OK
Content-Type: text/html

<html>...</html>

Leitura

HTTP é texto estruturado com linha inicial, cabeçalhos e corpo opcional.

Métodos e Status HTTP

Método Ideia
GET solicitar recurso
HEAD pedir só cabeçalhos
POST enviar dados
PUT criar ou substituir
DELETE remover
Classe Significado
2xx sucesso
3xx redirecionamento
4xx erro do cliente
5xx erro do servidor

Conexões Persistentes

Problema antigo

Abrir uma conexão TCP para cada objeto é caro.

Solução comum

Reaproveitar a conexão para várias requisições e respostas.

Cache HTTP

Cache reduz tráfego e latência, mas precisa validar se o conteúdo ainda serve.

Cabeçalho Ideia
Cache-Control política de cache
Expires data de expiração
Last-Modified última alteração
ETag identificador de versão
If-None-Match validação por ETag

Exemplo de resposta

HTTP/1.1 304 Not Modified

Mini-lab: HTTP Com curl

Ver cabeçalhos

curl -I http://example.com

Ver detalhes da conversa

curl -v http://example.com

Comparar HTTPS

curl -I https://example.com

O que observar

Status, cabeçalhos, Host, Content-Type, redirecionamentos e conexão.

Mini-lab: HTTP Local Com nc

Terminal 1

nc -l 8080

Terminal 2

curl -v http://127.0.0.1:8080/teste

O que aparece no nc

GET /teste HTTP/1.1
Host: 127.0.0.1:8080

Ideia

HTTP é uma conversa textual sobre TCP.

Mini-lab: Responder HTTP Manualmente

Terminal 1

printf 'HTTP/1.1 200 OK\r\nContent-Type: text/plain\r\n\r\nOla, HTTP!\n' | nc -l 8080

Terminal 2

curl http://127.0.0.1:8080

Resultado esperado

Ola, HTTP!

Servidor Web, no fundo, é um programa que fala HTTP corretamente.

Mini-lab: Conexões Web

Com algumas abas ou requisições Web abertas:

ss -tn '( dport = :80 or dport = :443 )'

O que observar

Informação Interpretação
ESTAB conexão TCP estabelecida
:80 HTTP
:443 HTTPS

Cuidado

Para e-mail, prefira demonstrar dig dominio MX. Testes SMTP externos podem ser bloqueados.
